# C-γ — SEO Landing Pages for /cross-network & /offline-transfer

Date: 2026-07-10
Status: Approved (design)
Part of: "Bucket C cleanup" — final item (C-α guess-code hardening + C-β frontend polish shipped).
Closes the three-page followup "多语言 landing 页 + sitemap" from
`memory/three-page-product-direction.md` and the SEO gap in `memory/seo-status-and-followups.md`.

## Goal

The two cross-network product modes — realtime cross-network transfer (`/cross-network`) and
async stored/download-link transfer (`/offline-transfer`) — are live SPA client routes with NO
crawlable static content and NO sitemap entries (asymmetric with the LAN home, which has
localized static landing pages). Add localized static SEO landing pages for both, symmetric
with the existing home-landing pattern, and register all in the sitemap.

## Approach (decided: Method 1)

Mirror the EXISTING home-landing model exactly:
- **English = the SPA route** (`/cross-network`, `/offline-transfer`) — no static file (a static
  file there would shadow the interactive SPA route). Improve the SPA's per-route `<title>` +
  meta description for these two routes.
- **Non-English (zh/ja/ko/de/fr) = static SEO landing pages** at `/<lang>/cross-network` and
  `/<lang>/offline-transfer`, generated by the SSG (`gen-pages.mjs`), each with a self-canonical,
  a full hreflang cluster (the 5 localized URLs + the English SPA route as `en`/`x-default`),
  JSON-LD, and a CTA linking into the live app route.
- Both modes' URLs (5 localized each + the 2 English SPA routes) go into `sitemap.xml`.

This is the SAME shape the home landing already uses: localized `/<lang>/` pages that hreflang-
point back to the English SPA `/`. No SPA route is shadowed; no new routing risk. English SEO for
these routes rests on the SPA `<title>`/meta + the sitemap + the localized pages' hreflang
cluster — exactly as the English home does today.

## Component 1 — localized copy modules (the content)

Two new content modules mirroring `web/scripts/pages/content/landing.mjs`'s structure and export
shape `export default { updated: "2026-07-10", langs: { zh, ja, ko, de, fr } }`:

- `web/scripts/pages/content/cross-network.mjs`
- `web/scripts/pages/content/offline-transfer.mjs`

Each `langs[lang]` object mirrors the landing copy structure: `title`, `description`,
`hero: { h1, pitch, cta }`, `how: { heading, steps[] }`, `why: { heading, items[{title,desc}] }`,
`compare: { heading, items[{title,body}] }`, `faq: { heading, items[{q,a}] }`, `learnHeading`,
`footer: { privacy, terms, security }`. Terminology mirrors `src/lib/i18n/*` for consistency.
Translate the 5 locales from a single English master (kept in a leading comment as source-of-
truth, per the article modules' convention); code/command blocks (none here) would stay English.

**Factual content each page must convey (accurately — do NOT overstate):**

- **cross-network** (`/cross-network`): realtime cross-network P2P transfer between two devices on
  different networks, paired by a 6-digit code (or its join link/QR), 15-min code TTL. Files stream
  peer-to-peer over an encrypted WebRTC channel; a TURN relay is used only when a direct path is
  impossible (symmetric NAT), and even then it relays ciphertext. E2E: X25519 + per-chunk
  AES-256-GCM; SAS 6-digit verification defeats a compromised signaling server. Minting a pairing
  code requires the sender to be logged in (attribution); the receiver joins anonymously. Free.
- **offline-transfer** (`/offline-transfer`): asynchronous "upload now, download later" via a
  zero-knowledge download link. The browser encrypts client-side before upload; the server stores
  ONLY ciphertext it cannot decrypt (the key lives in the link fragment, never sent to the server).
  Requires login to upload (it consumes storage). Optional burn-after-read + TTL expiry. Positioned
  as the async complement to the realtime mode.

## Component 2 — mode-landing page builder + template

Add a builder + template modeled on the existing `landing-template.mjs`/`build-pages.mjs`
(`buildLandingPages`/`renderLandingPage`), rendering one static HTML page per non-English lang:

- New `web/scripts/pages/mode-template.mjs` (or extend the landing template): `renderModePage({ lang, slug, spaPath, doc })` producing the `<html lang>` document with:
  - `<link rel="canonical" href="{absUrl of /<lang>/<slug>}">` (self).
  - hreflang cluster: for each of the 5 non-English langs `<link rel="alternate" hreflang="{BCP47}" href="{/<lang>/<slug>}">`, plus `hreflang="en"` → the English SPA route (`{spaPath}`) and `hreflang="x-default"` → the same English SPA route. (Same helper shape as `article-template.mjs`'s `alternates`.)
  - Open Graph (`og:locale` via `OG_LOCALE`), a `WebPage`/`SoftwareApplication` JSON-LD block (mirror the article template's JSON-LD).
  - Hero + how/why/compare/faq sections rendered from `doc`, a CTA (`.cta`) linking to `spaPath` (the live app route), header logo → `ctaHref(lang)`, the shared footer + a small "learn more" article-links list if trivially available (optional).
- New `buildModePages(modeDef, { slug, spaPath })` in `build-pages.mjs`: `validateLangs` against `LANDING_LANGS`, then `LANDING_LANGS.map(lang => ({ path: `/${lang}/${slug}/index.html` (via the existing path helper), html: renderModePage(...) }))`.

`slug`/`spaPath`: cross-network → slug `cross-network`, spaPath `/cross-network`; offline-transfer →
slug `offline-transfer`, spaPath `/offline-transfer`. The SSG (`.mjs` scripts) and the SPA router
(`.ts` src) can't share a module, so these paths must MATCH the router's `CROSS_PATH` (its value,
via `transfer-link`) and `OFFLINE_PATH` (`= "/offline-transfer"`) exactly — a Vitest can assert the
SSG constants equal the router's exported values so they can't silently drift.

## Component 3 — gen-pages wiring + sitemap

- `web/scripts/gen-pages.mjs`: `import crossNetwork from "./pages/content/cross-network.mjs"` and `offlineTransfer`; add `...buildModePages(crossNetwork, {slug:"cross-network", spaPath:"/cross-network"})` and the offline one to the `pages` array.
- `buildSitemap` (`build-pages.mjs`): extend its options to accept the mode pages, and emit, for each mode: the 5 localized URLs `absUrl(/<lang>/<slug>)` AND the English SPA URL `absUrl(/<slug>)`. Priority `0.8`, changefreq `weekly` (matching the landing pages). `lastmod` = the mode module's `updated`. Wire the mode defs into the `buildSitemap(...)` call in `gen-pages.mjs`.

## Component 4 — SPA per-route title + meta (English routes)

The SPA sets `document.title` from `messages[lang()].titleDefault` (App.svelte ~209) and the route
is known via `routeFromLocation` → `"cross"`/`"offline"` (`router.svelte.ts`). Add per-route
titles + meta descriptions so the English `/cross-network` and `/offline-transfer` routes carry
distinct, descriptive `<title>` + `<meta name="description">`:

- Add i18n keys `titleCross`/`titleOffline` (+ `descCross`/`descOffline` if the SPA sets a meta
  description; if it currently only sets `<title>`, add just the titles and set the description
  via the same reactive effect) across all 6 locales + `types.ts`.
- In the SPA's title effect, pick the title/description by the current `route` (`cross`/`offline`/
  `lan`), updating `document.title` and the `<meta name="description">` content. A pure helper
  `pageMeta(route, m): { title: string; description: string }` keeps it unit-testable (Vitest),
  mirroring the existing `routeFromLocation` pure-function + test style (`router.test.ts`).
