إعداد Device Inbox على خادم Linux يعمل دائمًا

آخر تحديث: 2026-08-09

ترجمة مؤرشفة

هذه الصفحة ترجمة عربية محفوظة للأرشيف. يجري صيانة منتج Relayium وتوثيقه الحالي بالإنجليزية والصينية المبسّطة، ولم يعد التطبيق نفسه يوفّر العربية. لذلك قد تختلف الشاشات والتفاصيل الموصوفة هنا عن السلوك الحالي.

النسخة الحالية: English · 中文

يرسل Device Inbox الملف من صفحته في المتصفح إلى خادمك أو جهاز NAS أو محطة العمل. يشفّره المتصفح، ولا يفكّه ويحفظه إلا الجهاز المستهدف.

يجب أن يستمر مستقبِل الخادم بعد إغلاق SSH وإعادة التشغيل. ينشئ المثبّت الموصى به المجلد وخدمة systemd فعلية. أما inbox run فللتشخيص في الواجهة أو للحاويات فقط.

تثبيت المستقبِل الدائم

سجّل الدخول مرة كمشغّل، ثم نزّل النص القصير وافحصه قبل منحه صلاحيات root. ينسخ بيانات الاعتماد دون عرضها، وينشئ حساب relayium مخصصًا، ويسجل مفتاح الاستقبال، ثم يثبت الوحدة المقوّاة ويشغلها الآن وبعد إعادة التشغيل.

relayium update
relayium login --device-name prod-backup-1

# Download, inspect, then install the always-on service:
curl -fsSLO https://relayium.com/inbox-server-install.sh
less inbox-server-install.sh
sudo sh inbox-server-install.sh --dir /srv/relayium-inbox
  • المجلد الموصى به هو /srv/relayium-inbox. لا تصل الخدمة المقوّاة إلى /root أو المجلد المنزلي لمستخدم آخر.
  • تعود ملكية الملفات والمفتاح الخاص إلى الحساب المخصص محدود الصلاحيات، لا إلى root.
  • لا تُنقل حالة استقبال قديمة إلى أرشيف مؤرخ قابل للاستعادة إلا بعد نجاح تشغيل الخدمة الجديدة.

فحص الخدمة والسجلات والملفات

تفحص الأوامر العملية والسجلات وحالة Relayium المحلية/المركزية والمجلد كلًا على حدة. لا تكفي حالة systemd الخضراء لإثبات صلاحية الحساب والمفتاح والمجلد.

sudo systemctl status relayium-inbox.service
sudo journalctl -u relayium-inbox.service -f
sudo -u relayium relayium inbox status --config-dir /var/lib/relayium-inbox/config
ls -la /srv/relayium-inbox
  • تصل الملفات إلى /srv/relayium-inbox ما لم تمرر --dir مختلفًا.
  • لا تُستبدل الملفات الموجودة؛ يحصل الاسم المتكرر على رقم آمن، ولا يُفتح المحتوى أو يُنفذ أو يُستخرج تلقائيًا.
  • تعرض «أجهزتي» الاسم القابل للتعديل وآخر IP رآه الخادم، وقد يكون عنوان NAT أو VPN.

السلوك عند انقطاع الاتصال أو التعطل

تنتظر المهمة المشفرة في Relayium أثناء غياب الخادم. الرفع لا يعني الحفظ؛ لا تظهر حالة الحفظ إلا بعد فك موثّق والتحقق والكتابة الدائمة.

  • يعيد systemd تشغيل العامل بعد فشل العملية وبعد إعادة تشغيل الخادم.
  • يبقى التنزيل الجزئي في مساحة تجهيز خاصة ولا يظهر كملف مكتمل.
  • يجعل السجل الدائم التعطل بعد الحفظ متكررًا بأمان: يُبلغ عن الحفظ نفسه دون إنشاء نسخة.
  • إذا اختفى المجلد لاحقًا فلا يعيد العامل إنشاءه تحت نقطة تركيب غائبة، بل يبلغ أن الأمر يحتاج إلى تدخل.

الإيقاف المؤقت أو الاستئناف أو الإزالة

شغّل أوامر الإدارة بالحساب ومجلد الإعداد نفسيهما. يحتفظ pause بالمفاتيح والطابور، ويتابع resume، ويحذف disable الحالة المركزية أولًا ثم المفاتيح الخاصة.

sudo -u relayium relayium inbox pause --config-dir /var/lib/relayium-inbox/config
sudo -u relayium relayium inbox resume --config-dir /var/lib/relayium-inbox/config
sudo -u relayium relayium inbox disable --config-dir /var/lib/relayium-inbox/config
  • لا تستخدم inbox run داخل نافذة SSH كإعداد دائم؛ سيتوقف عند إغلاقها.
  • يوقف systemctl disable --now العملية فقط. استخدم inbox disable لإلغاء صندوق الاستقبال ومفاتيحه أيضًا.

الأسئلة الشائعة

هل يرى Relayium أسماء الملفات أو النص الواضح؟

لا. يشفّر المتصفح البيان والملف ويغلق مفتاح المحتوى للجهاز المختار. لا يحتفظ المركز إلا بالنص المشفر وحالة التوجيه.

لماذا لا نستخدم /root/inbox؟

تعمل الخدمة الموصى بها دون root وتمنع الوصول إلى مجلدات المستخدمين. يمنحها /srv/relayium-inbox مساحة كتابة واحدة محدودة.

هل يمكن التثبيت يدويًا؟

نعم. يطبع relayium inbox service systemd-user أو systemd-system الوحدة والأوامر الخاصة بالجهاز، كما توجد إرشادات launchd وcontainer.

عندما تعرض الخدمة ready أرسل ملفًا من بطاقته في Device Inbox.
