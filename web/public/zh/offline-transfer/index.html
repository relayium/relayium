⇌Relayium

把文件变成一个加密链接发出去

当对方不在线时，先上传，再分享一个链接。你的浏览器会在上传前加密文件；服务器只保存它无法读取的密文——密钥始终只存在于链接里。

上传文件

四步完成一次传输

  1. 登录后选择一个文件——你的浏览器会在文件离开设备前于本地完成加密。
  2. 服务器只保存密文；解密密钥保留在链接片段中，绝不会发送给服务器。
  3. 分享这个下载链接（可选阅后即焚，以及你设定的有效期）。
  4. 接收方打开链接后，其浏览器会获取密文，并用链接中的密钥解密。

为什么选择 Relayium

  • 零知识 — 文件在浏览器里完成加密；服务器只经手它无法解密的密文。
  • 密钥就在链接里 — 解密密钥存放在 URL 片段（# 之后），浏览器绝不会把它发送给服务器。
  • 阅后即焚 + 有效期 — 可选择在首次下载后删除文件，也可设置有效期，到期后文件即消失。
  • 接收方无需账号 — 任何拿到链接的人都能下载；只有上传方需要登录。
  • 异步场景的补充 — 当对方暂时不在线时使用；若双方同时在线，可改用实时跨网络传输。
  • 也能用命令行 — 在终端里，relayium up 会上传并打印同一个链接，relayium down 在另一台机器上取回——CLI 与网页端共用同一条链接。

与其他方式相比

对比 WeTransfer / Dropbox 链接

那些服务能在服务器端读取你的文件；Relayium 的服务器只保存它无法解密的密文——密钥始终留在链接里。

对比实时模式

实时模式点对点直连，需要双方同时在线；这种模式则加密存储，方便接收方之后再取。

常见问题

服务器能读到我的文件吗？

不能——文件在你的浏览器里完成加密；服务器只保存密文，密钥永远不会到达服务器。

密钥在哪里？

在链接的片段里（# 之后）。浏览器不会把片段发送给服务器，因此只有拿到完整链接的人才能解密。

需要账号吗？

上传需要（会占用存储空间）。下载不需要——只要有链接即可。

能设置成只能下载一次吗？

可以——开启阅后即焚，并设置有效期。
