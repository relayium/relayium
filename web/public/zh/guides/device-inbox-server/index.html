在常开的 Linux 服务器上设置设备收件箱

最后更新: 2026-08-09

设备收件箱会把你在浏览器「设备收件箱」页面发送的文件送到自己的服务器、NAS 或工作机。浏览器负责加密，只有目标机器能够解密并写入磁盘。

服务器接收端必须在 SSH 窗口关闭和重启后继续工作。下面的推荐安装脚本会创建目录并安装真正的 systemd 服务；inbox run 只用于前台排错或容器入口。

安装常驻接收服务

先以管理员身份登录一次，再下载并检查短脚本，确认后才给它 root 权限。脚本不会打印凭据；它会创建独立 relayium 低权限账号、登记接收密钥、安装加固后的 unit、立即启动并设置开机自启。

relayium update
relayium login --device-name prod-backup-1

# Download, inspect, then install the always-on service:
curl -fsSLO https://relayium.com/inbox-server-install.sh
less inbox-server-install.sh
sudo sh inbox-server-install.sh --dir /srv/relayium-inbox
  • 推荐接收目录是 /srv/relayium-inbox。加固服务不能访问 /root 或其他用户的 home。
  • 接收文件和私钥由独立低权限账号持有，不归 root 进程。
  • 如果以前开过前台收件箱，只有在新服务成功启动后，旧状态才会移到带时间戳、可恢复的归档目录。

检查服务、日志和文件

下面四条命令分别核对进程、近期日志、Relayium 本地/服务端真实状态和落盘目录。systemd 显示绿色并不等于账号、密钥和目录一定可用。

sudo systemctl status relayium-inbox.service
sudo journalctl -u relayium-inbox.service -f
sudo -u relayium relayium inbox status --config-dir /var/lib/relayium-inbox/config
ls -la /srv/relayium-inbox
  • 未另传 --dir 时，文件落在 /srv/relayium-inbox。
  • 绝不覆盖已有文件；重名会安全编号。收到的内容不会自动打开、执行或解压。
  • 「我的设备」会同时显示可编辑备注名和服务端最近观察到的 IP；它可能是 NAT 或 VPN 地址。

服务器离线或崩溃时会怎样

服务器离线时，加密任务会在 Relayium 等待。「密文已上传」不等于「已保存」；只有完成认证解密、校验和持久落盘后才显示已保存。

  • 进程异常后 systemd 会重启，服务器重启后也会自动启动。
  • 未完成下载只存在于私有暂存区，不会暴露成完整文件。
  • 持久日志让提交后的崩溃保持幂等：重启后只补报同一次保存，不会复制文件。
  • 如果目录之后消失，worker 不会擅自重建，以免写到掉线挂载点下面；它会改为报告需要处理。

暂停、恢复或移除接收

管理命令必须使用同一个服务账号和配置目录。pause 保留密钥和队列；resume 继续；disable 先清除服务端，再在成功后删除私钥。

sudo -u relayium relayium inbox pause --config-dir /var/lib/relayium-inbox/config
sudo -u relayium relayium inbox resume --config-dir /var/lib/relayium-inbox/config
sudo -u relayium relayium inbox disable --config-dir /var/lib/relayium-inbox/config
  • 不要把 SSH 窗口里的 inbox run 当作永久方案；窗口关闭它就停止。
  • systemctl disable --now 只停止进程；如果还要撤销收件箱和密钥，请用 inbox disable。

常见问题

Relayium 能看到文件名或明文吗？

不能。浏览器会加密清单和文件字节，并把内容密钥封装给目标设备；中心只保存密文和路由状态。

为什么不放在 /root/inbox？

推荐服务刻意不用 root，并禁止访问用户 home。/srv/relayium-inbox 只给它一个边界清晰的可写区域。

可以手工安装吗？

可以。relayium inbox service systemd-user 或 systemd-system 会打印本机专用 unit 和命令，也有 launchd/container 说明；上面的可审阅脚本只是 Linux 服务器更短的路径。

服务显示 ready 后，就可以在「设备收件箱」页面从设备卡片发送文件。

打开「设备收件箱」
