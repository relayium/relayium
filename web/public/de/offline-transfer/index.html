⇌Relayium

Eine Datei als verschlüsselten Link senden

Wenn die andere Seite nicht online ist: jetzt hochladen und einen Link teilen. Dein Browser verschlüsselt vor dem Upload; der Server behält nur Chiffretext, den er nicht lesen kann — der Schlüssel verlässt nie den Link.

Datei hochladen

In vier Schritten übertragen

  1. Melde dich an und wähle eine Datei — dein Browser verschlüsselt sie lokal, bevor irgendetwas das Gerät verlässt.
  2. Der Server speichert nur den Chiffretext; der Entschlüsselungsschlüssel bleibt im Link-Fragment und wird nie an den Server gesendet.
  3. Teile den Download-Link (optional mit Löschung nach dem ersten Download und einer selbst gewählten Ablaufzeit).
  4. Die empfangende Person öffnet den Link; ihr Browser lädt den Chiffretext und entschlüsselt ihn mit dem Schlüssel aus dem Link.

Warum Relayium

  • Zero-Knowledge — Die Datei wird im Browser verschlüsselt; der Server hält immer nur Chiffretext, den er nicht entschlüsseln kann.
  • Schlüssel im Link — Der Entschlüsselungsschlüssel steckt im URL-Fragment (nach dem #), das Browser nie an den Server senden.
  • Löschung nach dem ersten Download + Ablauf — Optional die Datei nach dem ersten Download löschen und eine Lebensdauer festlegen, nach der sie verschwindet.
  • Kein Konto für den Empfänger — Jeder mit dem Link kann herunterladen; nur wer hochlädt, muss sich anmelden.
  • Ergänzung für asynchrone Fälle — Nutze dies, wenn die andere Seite gerade nicht online ist; für Echtzeit-Transfers über Netzwerke hinweg, wenn beide Seiten da sind.
  • Auch vom Terminal — Im Terminal lädt relayium up hoch und gibt denselben Link aus, relayium down holt ihn auf einem anderen Rechner ab — CLI und Web teilen sich einen Link.

Im Vergleich

Gegenüber WeTransfer-/Dropbox-Links

Diese können deine Dateien serverseitig lesen; Relayiums Server hält nur Chiffretext, den er nicht entschlüsseln kann — der Schlüssel bleibt im Link.

Gegenüber dem Echtzeitmodus

Echtzeit ist Peer-to-Peer und braucht beide Seiten online; dieser Modus speichert verschlüsselt, damit die empfangende Person später abrufen kann.

Häufige Fragen

Kann der Server meine Datei lesen?

Nein — sie wird in deinem Browser verschlüsselt; der Server speichert nur Chiffretext, und der Schlüssel erreicht ihn nie.

Wo ist der Schlüssel?

Im Fragment des Links (nach dem #). Browser senden Fragmente nie an Server, sodass nur jemand mit dem vollständigen Link entschlüsseln kann.

Brauche ich ein Konto?

Zum Hochladen ja (es nutzt Speicherplatz). Zum Herunterladen nein — nur der Link genügt.

Kann ich es einmalig machen?

Ja — aktiviere Löschung nach dem ersten Download und setze eine Ablaufzeit.
